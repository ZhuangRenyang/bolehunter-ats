# SmartAdmin 对标规划（迭代 32–35 路线图）

> 对标项目：[SmartAdmin](https://gitee.com/lab1024/smart-admin)（1024 创新实验室，MIT）
> 原则：**不照搬架构**（其四层架构/manager 层不引入，BoleHunter 三层够用）、**垂直业务优先**（功能全部贴猎头场景）、**每期独立可验收**（CI 绿 + 实机部署验证）。

---

## 一、差距分析总表

| 维度 | SmartAdmin 能力 | BoleHunter 现状 | 差距 | 价值 |
|------|-----------------|-----------------|------|------|
| 登录日志 | 独立分类（IP/浏览器/OS/成败/耗时） | 登录事件混在操作日志 | 高 | 安全审计刚需 |
| 数据变更记录 | 字段级 diff 可视化 | 只知谁改了、不知改了什么 | 高 | CRM 数据可信度 |
| 在线用户 | 会话列表 + 踢人 | 无 | 中 | 安全管控 |
| 数据脱敏 | 手机/邮箱按角色脱敏 | 明文（猎头电话是核心资产） | 中 | 数据安全（配置化开关）|
| 系统水印 | 全局水印防截图外泄 | 无 | 中 | 候选人数据保护 |
| 单号生成器 | 可配置规则单号 | 推荐无业务编号（裸 id） | 中 | 客户确认单等对外场景 |
| 文件中心 | 统一文件管理（预览/回收站） | 简历文件挂在候选人下 | 低中 | 简历量大时的管理 |
| 表格自定义列 | 用户级持久化 | 固定列 | 中 | 顾问个性化 |
| 帮助文档/反馈 | 右侧帮助面板 + 意见反馈 + 版本记录 | 无 | 低 | 产品感 |
| 服务器心跳 | CPU/内存/JVM 定时采集曲线 | 无 | 低中 | 运维可视化 |
| 枚举常量集中 | vue-enum 拒绝魔法数字 | 常量散落 | 内部 | 长期可维护性 |
| 多环境/返回码 | 5 env / 返回码集中 | 已接近（dev/test/prod + Code 枚举） | 低 | 已达标 |

## 二、分批迭代规划

### 迭代 32：安全审计双件套（高价值优先）

1. **登录日志**：新表 `sys_login_log`（username / ip / browser / os / 结果 / 耗时 / 时间）——登录/登出/锁定全埋点；管理页（筛选 + 导出）；登录失败 5 次锁定（迭代 15 已有）联动展示
2. **数据变更记录**：新表 `data_change_log`（table_name / record_id / field / old_value / new_value / operator / time）——MyBatis-Plus 数据变更拦截器自动采集（客户/候选人/职位启用）；前端在客户与候选人详情内新增「变更历史」抽屉，字段级前后值 diff 可视化
3. **验收**：改一个客户的电话 → 变更历史抽屉能看到「电话：138****0000 → 139****1111」

### 迭代 33：数据安全与治理

1. **数据脱敏**：手机号/邮箱展示按角色配置化（顾问全量、只读角色脱敏），复用 feature_flag + 角色判断
2. **系统水印**：全局浅色水印（用户名 + 时间），开关式（feature_flag：`sys_watermark`）
3. **单号生成器**：推荐单号（`REC-20261018-0001` 格式，按年月日重置序号）——客户确认链接与推荐详情展示
4. **在线用户**：Redis 会话扫描列表 + 强制下线

### 迭代 34：体验细节包

1. **表格自定义列**：客户/候选人表格的列显示配置（用户级持久化到后端）
2. **右侧帮助文档**：页面级说明面板（可折叠），说明当前页的字段与流程
3. **意见反馈**：登录用户提交反馈（新表 + 管理页查看）
4. **版本更新记录页**：从本路线图自动生成的 changelog 展示页

### 迭代 35：规范与工程

1. **枚举常量集中化**：前端 `constants/` 目录统一（推荐阶段/来源/状态全部走枚举常量，页面零魔法数字）
2. **服务器心跳**：定时采集 CPU/内存/JVM 指标 + 曲线页（管理端）
3. **文件中心**：简历文件统一列表（预览/下载/关联候选人跳转）
4. **README 功能清单与本文档对齐更新**

## 三、不做清单（明确不引入）

- SmartAdmin 的四层架构（controller/service/manager/dao）与 manager 层——三层对本项目规模足够
- uniapp 移动端——现有响应式 H5 已覆盖手机查看场景
- 国产数据库适配——目标用户用 MySQL
- 三级等保全量要求——开源版做安全要点（脱敏/水印/登录日志），等保级合规留给商业版
