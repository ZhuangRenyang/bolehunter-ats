## 项目背景与产品定位

本产品定位为 **猎头团队的内部作业系统（ATS）+ 客户关系管理（CRM）**：

- **角色模型收敛**：登录角色仅 管理员（ADMIN）+ 顾问（CONSULTANT），只读角色可选；企业与客户 HR 是**数据对象**（company 客户公司 / client_contact 联系人），不发登录账号——"企业是客户，不是用户；HR 是联系人，不是登录账号"。
- **商业边界（Open Core）**：开源版 = 完整作业闭环；客户 HR 门户、多租户 SaaS、AI 增强留给商业版。免登录推荐确认链接（confirm_token 列已预留）作为 v1.1 过渡方案。
- **北极星指标**：每周有效推荐数。

**决策**：用户拍板 **B 方案（精简重建）**——后端全升 + 前端 Vue3 只重建 ATS 页面（约 14 页），冻结的老 C 端页面（求职者/企业/投递/聊天）不迁移。

**前端 Vue2 → Vue3（新目录 `bolehunter-ats-web`）**：

## 连库冒烟（22:22 – 23:00，通过 ✓）

**环境**：MySQL 8.4（root/root）✓、Redis 未启动（无碍，JWT 无状态）；本机无 `bolehunter` 库 → 导入 `sql/bolehunter.sql`（22 表基线）+ 依序应用 iter0-3 迁移（9 新表/8 字典/54 权限）。

**冒烟修复 6 个真实问题**：
1. Windows JVM 默认 GBK 与 `mandatory-file-encoding: UTF-8` 冲突 → 插件 `jvmArguments -Dfile.encoding=UTF-8`
2. MP 3.5 `MybatisEnumTypeHandler` 从 extension 包移到 core 包（application.yml + GroupMapper.xml 两处）
3. freemarker 2.3.30 缺 jakarta JSP 支持 → 升 2.3.33
4. **幽灵端口 65051**：WorkBuddy 环境变量 `SERVER__PORT` 被 Spring 宽松绑定读走 → 启动显式 `--server.port=5000`
5. dev.yml 数据库密码与本机不符
6. **SB6 禁止 `allowedOrigins("*")` + `allowCredentials(true)`**（所有老 Lin 项目迁 SB3 必踩）→ `allowedOriginPatterns("*")`

**另发现自研拦截器鉴权语义 bug（最有价值）**：旧 talelin 语义中 `@PermissionMeta` 单独存在也要求登录+权限校验，初版只认 `@GroupRequired` → 带 @PermissionMeta 的接口被当成公开接口、LocalUser 为 null（新建客户 `owner_id=null` 实证暴露）。修复后 `owner_id=1` 验证通过。

**冒烟结论（12/12）**：登录 JWT、权限、部门树、字典、开关、客户新建（8300）、客户分页+keyword、候选人新建（8500）、查重、job-options 联表、未授权拒绝（10012）、Excel 模板下载。

## 迭代 29f 修复：工作台卡片排列不整齐（10/19）

## 迭代 38 修复：四个页面直链 404 + 生产库迁移漏执行（10/19 20:05）

**现象**：`/admin/login-log` 打开是应用内 404 页；顺带发现 `/setting/heartbeat`、`/setting/file-center`、`/setting/changelog` 同样 404。

**根因（三层）**：
1. **路由漏注册**：四页在 `router/stage.js`（菜单数据源，`inNav: true`）与 `view/**` 下都存在，但 `router/index.js` 从未注册对应 path → 命中 `:pathMatch(.*)*` 兜底 404。菜单点击与直链都走不通。
2. **登录日志分页结构不匹配**：`AuditController.loginLogPage` 直接返回 `IPage`（序列化为 `records/current/size`），前端统一读 `items/total` → 即使路由修好表格也恒空。改走 `PageUtil.build` 输出 `PageResponseVO`。
3. **生产库四个迁移从未执行**：`schema_history` 只有 iter0-7（10/17 基线对齐），而服务器 `~/bolehunter-ats/bolehunter-ats/sql` 是 10/17 的旧副本、缺 iter8/9/10/11 文件；`MIGRATION_DIR` 只认宿主机挂载目录，于是 `sys_login_log`、`data_change_log`、`sys_user_preference`、`feedback`、`collect_link` 表与 `candidate.audit_status`、`recommendation.order_no` 列全部缺失——登录日志/文件中心接口 500，自助收集链接与脱敏/水印开关也从未可用。

**修复**：
- `router/index.js` 补注册四路由（`/admin/login-log`、`/setting/heartbeat`、`/setting/file-center`、`/setting/changelog`）；用 `comm` 对比 stage 路由与 index 注册，21 条菜单路由现已零缺失
- `AuditController` 分页改 `PageUtil.build(iPage)`
- 生产库：先 `mysqldump` 备份（`~/backups/bolehunter_before_iter8-11_*.sql`）→ 同步 4 个迁移文件 → 重启 backend 触发自动迁移，四脚本全部成功记账（iter10 215ms / iter11 173ms / iter8 159ms / iter9 156ms）
- **加固**：迁移脚本 `COPY sql /app/sql-bundled` 内置进镜像，`DbMigrationService.scanScripts()` 合并扫描「镜像内置 + MIGRATION_DIR」，同名以挂载目录为准 → 只 pull 镜像不同步源码的服务器也不会漏迁移
- `data/changelog.js` 追加 v1.1.5

**验证**：四个 URL 均 200；`login-log/page` 返回 `{"total":1,"items":[...]}`（真实登录记录）；`/audit/files`、`/audit/heartbeat` 200；`candidate/page`、`collect-link/list` 200；镜像内 `/app/sql-bundled` 14 个脚本，启动日志"数据库结构已是最新"。

**教训**：
1. 页面"存在"≠"可用"——`view/*.vue` 有文件、菜单有入口、构建不报错，但路由没注册就是死链；新页面验收必须覆盖「菜单点击 + 直链刷新」两条路径
2. 分页接口统一走 `PageResponseVO`，直接返回 `IPage` 会在前端静默变空表（字段名 `records` vs `items`）
3. 迁移脚本依赖宿主机挂载目录是错误的交付形态——**发版产物必须自包含**，镜像内置才是"一键升级"闭环的前提
